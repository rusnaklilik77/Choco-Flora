# Choco-Flora

Сайт-меню для Choco-Flora на React + Vite. Цена, описание, меню и темы
оформления хранятся в Firebase (Firestore), а сами фото — не грузятся на
сервер, а берутся по ссылке (например, с Google Диска).

## Что нового в этой версии

- **Панель администратора разделена на 2 вкладки.** Вместо одного длинного
  экрана — «🍫 Товары» и «🎨 Темы». При нажатии на вкладку открывается
  всплывающее окно именно с тем разделом, который вы выбрали.
- **Переключатель языка сайта.** В шапке сайта есть кнопки RU / RO / EN —
  переключают язык интерфейса (заголовки, подписи, кнопка звонка и т.д.)
  сразу, без перезагрузки страницы. Выбор запоминается в этом браузере.
  Сами позиции меню (название/цена/состав) вводятся админом на одном
  языке и не переводятся автоматически.
- **Фото по ссылке, а не загрузкой файла.** Для фона темы, падающих
  картинок-стикеров и фото товаров теперь просто вставляется ссылка —
  удобнее всего хранить фото на Google Диске и вставлять ссылку
  «Поделиться» на файл. Приложение само превращает такую ссылку в прямую
  (рабочую как `<img src>`).
- **Абсолютно все темы редактируются и удаляются.** Не только свои
  созданные темы, но и встроенные (Осень, Зима, Хэллоуин и т.д.) — теперь
  это обычные записи в базе, а не «зашитый» в код список. Можно
  переименовать, поменять цвет, фон, стикеры или категорию, можно удалить
  (кроме самой последней оставшейся темы — сайту нужна хотя бы одна).
- **Firebase хранит только текст**: название, цену, описание и ссылки на
  фото. Самих картинок в базе нет — поэтому бесплатного плана Firestore
  хватит с огромным запасом, независимо от количества и размера фото.

## Как вставить фото с Google Диска

1. Загрузите фото на Google Диск.
2. Нажмите на файл правой кнопкой → **Открыть доступ** (Share).
3. В настройках доступа выберите **«Все, у кого есть ссылка»** → роль
   **«Читатель»** (Viewer). Это обязательно — если доступ закрыт, фото не
   загрузится ни у одного посетителя сайта.
4. Нажмите **«Скопировать ссылку»** — получится ссылка вида
   `https://drive.google.com/file/d/ФАЙЛ_ID/view?usp=sharing`.
5. Вставьте её как есть в админке (поле фона темы, поле стикера или поле
   «Фото» у позиции меню). Приложение само конвертирует её в прямую
   ссылку на изображение.

Точно так же можно вставлять ссылки на фото с любого другого хостинга
(Яндекс.Диск с прямой ссылкой, imgur, собственный сайт и т.п.) — если
это не Google Диск, ссылка используется как есть.

### Почему не полноценная интеграция с Google Диском (выбор файла прямо из окна Диска)

Такая интеграция («открыть окно выбора файла с Диска» — Google Picker)
требует создать в Google Cloud Console свой собственный OAuth Client ID
и API-ключ, привязанные к вашему Google-аккаунту — это не то, что можно
один раз «зашить» в проект за вас, ключи должны быть именно вашими и
настроенными на ваш домен. Вариант со ссылкой даёт тот же результат
(фото хранится и обновляется на Диске, сайт лишь на него ссылается), но
работает сразу, без регистрации отдельного приложения в Google Cloud.
Если позже понадобится именно окно выбора файла — дайте знать, это можно
добавить отдельным шагом, когда будут готовы такие ключи.

## Запуск (без Firebase — локальный режим)

```bash
npm install
npm run dev
```

Пока не заданы переменные окружения Firebase, сайт работает в **локальном
режиме**: меню, темы и вход администратора хранятся в localStorage
браузера. Удобно, чтобы сразу всё проверить, ничего не настраивая.

## Подключение Firebase (чтобы данные были общими для всех посетителей)

1. Зайдите на https://console.firebase.google.com и создайте проект
   (бесплатно, без привязки карты).
2. В разделе **Build → Firestore Database** нажмите «Создать базу данных»
   (режим test mode подойдёт для старта, ниже — как закрыть его правильно).
3. В разделе **Project settings → General → Your apps** добавьте веб-приложение
   и скопируйте значения `firebaseConfig`.
4. Скопируйте `.env.example` в `.env` и вставьте туда эти значения:

   ```
   VITE_FIREBASE_API_KEY=...
   VITE_FIREBASE_AUTH_DOMAIN=...
   VITE_FIREBASE_PROJECT_ID=...
   VITE_FIREBASE_STORAGE_BUCKET=...
   VITE_FIREBASE_MESSAGING_SENDER_ID=...
   VITE_FIREBASE_APP_ID=...
   ```

5. Перезапустите `npm run dev` — теперь меню, темы и ссылки на фото
   хранятся в Firestore и обновляются в реальном времени у всех
   посетителей.

При первом запуске с настроенным Firebase приложение само создаёт нужные
коллекции и документы (включая все встроенные темы — как обычные
редактируемые записи):

```
menu/                  — позиции меню (name, price, composition, photos[])
themes/                — все темы, включая встроенные (name, colors, bgImage, particleImages[], category)
settings/site          — { themeId }              — текущая тема сайта
settings/admin         — { login, password }       — логин/пароль админа (по умолчанию admin/admin)
```

Логин и пароль администратора можно поменять прямо в Firestore Console,
отредактировав документ `settings/admin`.

### Правила безопасности Firestore (рекомендуется)

По умолчанию test mode в Firestore разрешает читать/писать всем в течение
30 дней, а потом закрывает доступ полностью. Чтобы сайт продолжал работать
и после этого, но данные не мог свободно менять кто угодно из интернета,
задайте правила примерно так (Firestore Console → Rules) — используется
готовый файл `firestore.rules` из этого проекта:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /menu/{docId} { allow read: if true; allow write: if true; }
    match /themes/{docId} { allow read: if true; allow write: if true; }
    match /settings/{docId} { allow read: if true; allow write: if true; }
  }
}
```

⚠️ **Важно про безопасность.** Проверка пароля админа происходит на стороне
браузера (клиент читает `settings/admin` и сравнивает значения), поэтому
человек с техническими навыками теоретически может писать в базу напрямую
через Firestore API, минуя пароль сайта. Для полностью надёжной защиты
понадобится Firebase Authentication — это следующий шаг, если проект
вырастет и появится риск целенаправленной атаки.

## Сборка для продакшена

```bash
npm run build
npm run preview
```

Готовые файлы появятся в папке `dist/`.

## Деплой на Vercel

1. Загрузите проект в Git-репозиторий (GitHub/GitLab/Bitbucket) или
   используйте `vercel` CLI прямо из папки проекта.
2. На https://vercel.com нажмите **Add New → Project** и выберите репозиторий
   (Vercel сам определит, что это Vite-проект).
3. В **Project Settings → Environment Variables** добавьте те же переменные,
   что и в `.env` (`VITE_FIREBASE_API_KEY` и т.д.).
4. Нажмите **Deploy** — через минуту сайт будет доступен по ссылке `*.vercel.app`.

Всё (Vercel Hobby-план + Firebase Firestore Spark-план) бесплатно.

## Возможности

- Экран загрузки с логотипом и розовым «лучом» вокруг него.
- Адаптивная вёрстка: 2 карточки товара в ряд на телефоне, 4 — на компьютере/планшете.
- Темы оформления: готовые (времена года, праздники, эксклюзив) и свои —
  **все до одной редактируются и удаляются** прямо в админке; фон и
  падающие картинки задаются ссылкой (удобно — с Google Диска).
- Панель администратора: две вкладки-попапа — **Товары** (добавить/
  редактировать/удалить позицию меню) и **Темы** (выбрать активную,
  создать/редактировать/удалить любую тему).
- Переключатель языка сайта (RU / RO / EN) в шапке.
- Работает без Firebase «из коробки» (localStorage), и автоматически
  переключается на Firebase, как только заданы переменные окружения.
